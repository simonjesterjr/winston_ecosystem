## 4. Decisions Made

### Decision 1: Mode D is a portfolio fulfillment mode, not Plan D
- **Choice:** Store `fulfillment_mode: mode_d` inside `portfolios.fulfillment_packaging_policy`. Do not add a rung to `FulfillmentPackagingPolicy::ALL_RUNGS` and do not put `mode_d` in `leap_fulfillment`.
- **Why:** Plan A/B/C already choose one instrument. A covered call is a second leg on a long.
- **Alternatives considered:** A new `fulfillment_mode` column. Deferred; the JSON key is enough for an opt-in.
- **Reversibility:** easy
- **Promote to ADR?** yes, when the desk page exists. ADR-018 stays Mode C only.

### Decision 2: The call is not a second Turtle position
- **Choice:** Covered-call state is journals on the stock `Position`. `SignalEvaluation#open_positions_for` ignores a position whose journals are only `covered_call`.
- **Why:** Pyramid level is `positions.size + 1`.
- **Reversibility:** easy
- **Promote to ADR?** no

### Decision 3: Phase 1 does not send
- **Choice:** Tasks are `hitl`. Stock exit is suppressed while a short call is open. Buy-to-close is the unwind task.
- **Why:** ADR-009. The 2026-09-23 IBM long-call BUY was rejected for permissions. Mode D does not retry that BUY.
- **Reversibility:** easy
- **Promote to ADR?** no

## 9. Risks & Technical Debt

- Uncommitted code on `main` in two repos. Easy to mix with the unrelated broker_gateway dirty files if someone runs `git add .`.
- A pending skip task does not block a later sell on that same lot; a pending sell does. Confirming the sell journal would book it in Winston without sending to Interactive Brokers. There is no confirm-path spec for that journal yet.
- `CoveredCallCandidates` inherits LeapCandidates private HTTP helpers. A future edit to `live_row` can change the covered-call walk without a LEAP spec failing.
- First-unit and other skips mint a `hitl` task. Daily Analysis will keep that task pending, so the desk can fill with skips before a human expires them.
