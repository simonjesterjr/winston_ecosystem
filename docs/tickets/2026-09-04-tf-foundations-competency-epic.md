# Ticket: Trend Following six-principles competency program

**Status:** Proposed  
**Priority:** P2 — strategic architecture; does not preempt P0 capital/data  
**Date:** 2026-09-04  
**Monolith:** cross (WUT lab, Wv2 desk, DM parquet, Cromwell attention)  
**Tracker:** [`2026-09-04-tf-foundations-INDEX.md`](2026-09-04-tf-foundations-INDEX.md)

## Problem

Winston has a mature Trend Following (TF) factory (recipe → fingerprint → observation → human-gated desk) and no single competency model that says **which of the six trading layers we actually run**. Bake-offs, Kelly overlays, Turtle heat, and Evolution Mode sketches can each look like progress while the stack stays half-instrumented.

Without this program we risk:

- Another in-sample bake-off cell treated as Shannon proof  
- Kelly-on-the-desk because the engine exists  
- Evolution Mode before walk-forward and sit-vs-kill  
- Discipline doctrine leaking through un-audited size/packaging hatches  

## Desired outcome

1. Accepted competency grades (librarian pages + analysis pointer).  
2. One principle ticket per layer, each listing **new work** and **existing tickets to finish first**.  
3. Plans and ADRs spawned from those tickets, not from essay quotes.  
4. Operator can answer: “are we managing this principle, or is it a gap?” without a new research session.

## Children

- P1 residual signal / out-of-sample  
- P2 tails / ruin / uncertainty  
- P3 live sizing / Capital Authority  
- P4 compounding / champion freeze  
- P5 desk discipline completion  
- P6 map vs territory / model death  

## Acceptance

- [ ] Operator accepts grades (or amends them in the librarian pages)  
- [ ] Each child ticket either scheduled, deferred with reason, or merged into an existing in-flight ticket  
- [ ] No Evolution Mode work opened from this epic  
- [ ] P0 corporate-action and scored-session tickets remain first in the queue
